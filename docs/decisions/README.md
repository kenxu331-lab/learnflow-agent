# Architecture Decision Records

本目录用于记录会影响模块边界、依赖、数据流、安全或长期维护的架构决策。本轮只建立模板，不预先创建尚不存在的未来模块决策。

建议文件名为 `NNNN-short-title.md`，编号按创建顺序递增。普通实现细节不需要单独创建 ADR；如果决策被替代，应保留原记录并更新状态，而不是删除历史。

## ADR 模板

复制以下模板创建新的决策记录：

```markdown
# ADR-NNNN：<决策标题>

- 状态：提议 | 已接受 | 已废弃 | 已替代
- 日期：YYYY-MM-DD

## 决策背景

描述需要解决的问题、当前约束、相关模块和不做决策的后果。

## 可选方案

### 方案 A：<名称>

- 优点：
- 缺点：
- 影响范围：

### 方案 B：<名称>

- 优点：
- 缺点：
- 影响范围：

## 最终选择

说明最终采用的方案及其适用范围。

## 选择理由

说明选择依据，包括一致性、可测试性、安全性、复杂度、性能或维护成本。

## 技术代价与风险

记录新增复杂度、迁移成本、已知限制、失败模式和后续需要观察的指标。

## 后续行动

列出需要实现、验证、监控或在未来重新评估的事项。
```
