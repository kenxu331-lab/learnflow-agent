# AI 应用开发岗位：LearnFlow 项目经历

## 可直接放入简历

### LearnFlow Agent｜基于浏览器学习上下文的 AI 知识助手

项目角色：按实际贡献填写｜项目时间：按实际起止时间填写
技术栈：Python、FastAPI、Pydantic、SQLite、OpenAI-compatible API、Function Calling、SSE、TypeScript、Chrome Manifest V3、Obsidian Markdown

项目简介：面向技术文档学习场景，构建浏览器扩展与本地后端协同的 AI 助手，打通网页上下文感知、流式问答、知识提炼、证据核验及 Obsidian 确认归档闭环。

- **Agent 工具调用：** 基于模型原生 Function Calling 实现轻量业务 Agent，接入原文读取、知识查询、提炼、任务结果查询及归档预览 5 类工具；通过 Pydantic 参数校验、工具白名单、步数/超时/上下文预算限制执行范围，支持学习解释、成果整理及检查理解后提炼等复合任务。
- **知识质量控制：** 设计“学习事件 → Knowledge Draft → 原子 Claim → 独立证据核验 → PublishCandidate”流水线，建立来源证据注册与章节锚点关联；校验模型结构化输出和证据 ID，区分教程事实、用户理解与 AI 解释，避免将历史 AI 回答直接作为事实证据。
- **异步任务与去重：** 使用 SQLite 持久化提炼任务、事件高水位和批次指纹，结合租约、有限重试及状态机实现任务恢复与重复提交控制；对知识候选执行规范化精确去重及文本相似提示，避免把相似知识直接合并。
- **人机协同归档：** 实现“生成合并 Markdown Diff → 用户确认 → 版本复核 → 写入回执”流程，将确认绑定至知识版本、Vault、文件哈希及计划摘要；结合跨进程锁、原子文件替换和意图记录，实现重复确认幂等、中断恢复及冲突转人工审查，模型不具备直接确认写入权限。
- **全链路产品集成：** 基于 Chrome MV3 构建学习侧栏与独立宽屏工作台，通过 SSE 展示回答增量及工具事件；按章节管理快照、选区和可恢复会话，并以 pytest、Vitest 覆盖任务恢复、跨章节隔离、核验失败和归档并发等关键路径。

## 一分钟项目介绍

LearnFlow 是一个面向技术文档学习的 AI 应用。用户在浏览器阅读教程时，扩展采集当前章节和选区，后端 Agent 可以根据问题读取原文、查询已有知识，必要时触发异步提炼。它与普通聊天封装的区别是，我把知识生成、事实核验和文件写入拆成了不同阶段：候选知识要关联证据并接受独立 Claim 核验，归档前展示真实 Diff，只有用户点击确认才写入 Obsidian。工程上主要处理了任务中断恢复、跨章节状态隔离，以及预览后文件变化和重复确认等一致性问题。

“我”仅在本人能够解释并承担这些实现时使用；如是团队项目，改成实际负责的部分。可说明使用 AI 编程工具协作，不应捏造开发方式。

## 三个值得掌握的技术点

1. **模型决策与应用权限分离：** 模型可以提出工具调用，但参数、来源范围和确认权限必须由应用校验；Prompt 不是权限系统。
2. **生成和核验分离：** Knowledge Draft 不等于通过核验的 PublishCandidate；独立核验不能直接信任上一轮模型答案。
3. **跨资源一致性：** SQLite 与 Markdown 文件不能简单当作一个事务，应结合不可变计划、内容哈希、意图日志、幂等键和恢复状态机。

## 面试准备

1. **为什么这是 Agent，不只是调用一次大模型？** 说明有限的“模型决策 → 工具执行 → 结果反馈 → 下一轮决策”循环，以及异步等待/用户确认时停止执行的边界。
2. **文件写入成功但数据库回执未提交，如何恢复？** 结合 applying/approvedAt、文件前后哈希、意图记录讲清楚何时恢复回执、何时再次确认、何时 needs_review。
3. **如何减少错误知识沉淀？** 从证据注册、ID 校验、教程事实来源限制、独立 Claim 核验、发布资格和用户确认逐层说明；同时承认当前没有量化核验准确率。
